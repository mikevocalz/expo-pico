PICO Platform Service SDK moves from 1.0.0 to each artifact's newest stable release on the Volcengine Maven: `platform-service-{auth,achievement,friend,iap,leaderboard,social}` 1.1.2, `platform-service-{push,sport}` 1.1.3, `pps_sdk_base` 1.1.3. `compliance`, `entitlement` and `speech` have never published past 1.0.0 and stay there. Versions are now per artifact (`PPS_SERVICE_VERSIONS` in `ppsArtifacts.ts`); one shared version would have requested coordinates that do not exist. The generated `constraints` block and the project-level resolution pin use the same per-artifact map, and `pps_sdk_base` is forced to 1.1.3 for every service. The 1.1.2 services' POMs name 1.1.2, but `pps_sdk_base` 1.1.2 and 1.1.3 have the same public API. No member the wrapped packages call was removed or changed. `sdkVersion` on each bridge reports the new version.

An `android/` generated by an earlier version picks up the new pins on the next `npx expo prebuild`; `--clean` is not needed. The plugin now rewrites its PPS dependency block, its `app/libs` block and the project-level resolution pin in place instead of skipping them when their marker exists. `expo-pico-doctor` reports pins under `pps-coordinate-version-skew`, now checked per artifact: a stale line inside the generated block gets "run `npx expo prebuild`", a hand-written one gets "remove it".

`@expo-pico/app-kit` no longer tells you to declare `com.pico.pps:platform-service-*` yourself or put a PPS AAR in `android/app/libs/`. `expo-pico-core` declares the Maven artifacts, and its `fileTree` excludes PPS AARs by name.
