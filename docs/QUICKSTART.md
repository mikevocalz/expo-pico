# Quickstart

This guide creates an Expo SDK 58 app with `@expo-pico/core` and a native React Native diagnostics panel for PICO. The starter opens as a 2D panel. Adding a 3D renderer and enabling immersive launch is a separate step below. Normal release-package installs and app builds do not require a manual AAR download or rebuild.

Deeper references once you're up and running:

- [README](../README.md): package overview
- [Installing from GitHub](./INSTALL-FROM-GITHUB.md): release packages and required peers
- [docs/EAS.md](./EAS.md): hosted builds plus PICO Store submission

## 0. Prerequisites

- Node 22.18+ and yarn 1.x (or `npm`). The repo and templates are written for yarn; swap to `npm` / `pnpm` if you prefer.
- Android Studio with:
  - Command-line tools installed.
  - `ANDROID_HOME` on your `PATH`.
  - The Android SDK, build tools, NDK and Java versions required by Expo SDK 58. Use the versions generated by Expo and install missing components through Android Studio's SDK Manager; do not force the old Android 34 toolchain.
- A PICO device in developer mode.
  - Settings → About → tap Build Number 7 times → developer options unlock.
  - Enable USB debugging.
  - First `adb install` on a new device prompts for RSA trust on the headset.
- PICO developer credentials when using Platform Services or testing an immersive OS 5 launch. Register the app at [developer.picoxr.com](https://developer.picoxr.com/). Compiling the starter does not require an app ID; device entitlement is discussed under immersive setup below.

## 1. Scaffold a new Expo app

Two paths. Pick one.

Shortcut: use the PICO template. Skips steps 2 and 3 entirely. `expo-pico-core` is already wired, `app.config.ts` is preconfigured, and `App.tsx` includes a live diagnostics HUD. Jump to step 4.

```bash
npx create-expo-app@latest my-pico-app --template https://github.com/mikevocalz/expo-pico/tree/release%2Ftemplate
cd my-pico-app
```

Or start from the default template and install the plugin yourself (more flexibility if you're retrofitting an existing app):

```bash
npx create-expo-app@latest my-pico-app --template default@sdk-58
cd my-pico-app
```

Nothing PICO-specific yet. Check that Metro starts before adding the PICO native modules:

```bash
yarn install
npx expo start
```

Kill the dev server once you see the QR code. We're about to switch to the Android / PICO path.

## 2. Install the `expo-pico-core` plugin

```bash
npm install "github:mikevocalz/expo-pico#release/core" react-native-nitro-modules@1.0.0-alpha.nightly.120.g33ef045b96c0
```

Only `@expo-pico/core` and its Nitro peer are required for base build wiring. The packages install from GitHub release branches, not npm. Add siblings and their shared-service peer as documented in [Installing from GitHub](./INSTALL-FROM-GITHUB.md).

**No PICO app ID is required to generate or compile the PICO flavor.** An immersive OS 5 launch can still be blocked by the headset's entitlement service without a registered ID. Account and payment calls also require their service credentials.

## 3. Configure `app.config.ts`

Create `app.config.ts` alongside the generated `app.json`. This extends the existing config, including the default template's Router plugins:

```ts
import { ExpoConfig, ConfigContext } from 'expo/config';

export default ({ config }: ConfigContext): ExpoConfig => ({
  ...config,
  name: 'my-pico-app',
  slug: 'my-pico-app',
  newArchEnabled: true, // required
  // 'default' — a locked orientation writes android:screenOrientation onto
  // MainActivity and overrides the panel dimensions the plugin writes via
  // defaultWidth/defaultHeight. `expo-pico-doctor` flags anything else.
  orientation: 'default',
  android: {
    ...config.android,
    package: 'com.example.mypicoapp',
  },
  plugins: [
    ...(config.plugins ?? []),
    [
      '@expo-pico/core',
      {
        // Choose 'pico-os5' for PICO 4 / 4 Ultra, 'pico-swan' for Swan.
        // 'mobile' turns the plugin into a mostly-no-op for phone builds.
        xrMode: 'pico-os5',

        // Start with the React Native panel. Add a renderer before
        // changing this to 'vr' or 'mr' for an immersive activity.
        appType: '2d',

        buildVariant: 'pico', // writes the PICO flavor manifest

        // Required for relevant Platform Services and OS 5 immersive launch:
        platformService: {
          picoAppId: process.env.PICO_APP_ID ?? process.env.PICO_PLATFORM_APP_ID,
          picoAppKey: process.env.PICO_PLATFORM_APP_KEY,
        },

        // Declare capabilities only when an implemented renderer/API uses them.
        // These flags alone do not implement XR tracking or passthrough.
        // handTracking: true,
        // passthrough: true,
        // refreshRates: [72, 90, 120],
        // eyeTracking: true,
      },
    ],
  ],
});
```

Every plugin option is documented in [expo-pico-core's README](../packages/expo-pico-core/README.md#plugin-options).

### Lint before you prebuild

```bash
npx expo-pico-doctor
```

The doctor checks common misconfigurations before `expo prebuild` mutates native files. The `identity.missing` finding is informational about build configuration: the PICO flavor still compiles. For an OS 5 immersive configuration it also explains the device entitlement requirement. Supply service credentials before calling login, IAP or leaderboards.

## 4. Regenerate native projects

```bash
npx expo prebuild --clean --platform android
```

This creates `android/` **without editing Gradle or AndroidManifest by hand**, even when no PICO Developer Console app ID has been set. Generated files include:

- `flavorDimensions "device"` plus `mobile` / `pico` product flavors
- A PICO-flavor manifest for the selected app type; this starter uses `2d` and does not opt into immersive launcher categories
- `<uses-native-library android:name="libopenxr_loader.so"/>`
- `ndk { abiFilters 'arm64-v8a' }` on the pico flavor
- `PicoCorePackage` in the autolinked package list, through `@expo-pico/core`'s `react-native.config.js`

Generated Nitro bindings and the Eskiu runtime come from the core release package. Prebuild writes Maven dependency declarations; Gradle resolves those dependencies in the next step. Keep custom app configuration outside the generated `android/` tree so a clean prebuild can reproduce it.

## 5. Run on a connected PICO

```bash
npx expo run:android --variant picoDebug
```

This compiles and installs the pico flavor APK. The first build downloads dependencies and compiles native modules; later builds reuse the normal Gradle cache.

If you don't have a headset connected right now, use the mobile flavor to confirm the plugin didn't break anything:

```bash
npx expo run:android --variant mobileDebug
```

The mobile flavor is deliberately mostly-no-op. `expo-pico-core` doesn't touch the mobile manifest beyond `<queries>` deferred to the pico flavor.

## 6. Add a diagnostics panel

The PICO template already includes a diagnostics panel. To add one to another app, use this component in `App.tsx`, or in a route component when using the default Expo Router template:

```tsx
import React, { useEffect, useState } from 'react';
import { ScrollView, StyleSheet, Text } from 'react-native';
import {
  getPicoDiagnostics,
  getPicoRuntimeInfo,
  getPlatformSdkProbe,
  formatDiagnostics,
  type PicoDiagnosticsReport,
  type PicoPlatformSdkProbe,
} from '@expo-pico/core';

export default function App() {
  const info = getPicoRuntimeInfo();
  const [report, setReport] = useState<PicoDiagnosticsReport | null>(null);
  const [probe, setProbe] = useState<PicoPlatformSdkProbe | null>(null);

  useEffect(() => {
    (async () => {
      setReport(await getPicoDiagnostics());
      setProbe(await getPlatformSdkProbe());
    })();
  }, []);

  return (
    <ScrollView style={styles.root} contentContainerStyle={styles.body}>
      <Text style={styles.h1}>Runtime info</Text>
      <Text style={styles.mono}>{JSON.stringify(info, null, 2)}</Text>

      <Text style={styles.h1}>Platform SDK probe</Text>
      <Text style={styles.mono}>{JSON.stringify(probe, null, 2)}</Text>

      <Text style={styles.h1}>Diagnostics</Text>
      <Text style={styles.mono}>{report ? formatDiagnostics(report) : '…'}</Text>
    </ScrollView>
  );
}

const styles = StyleSheet.create({
  root: { flex: 1, backgroundColor: '#0b0d1a' },
  body: { padding: 20 },
  h1: { color: '#ffffff', fontSize: 16, fontWeight: '700', marginTop: 16 },
  mono: { color: '#d0d4f0', fontFamily: 'monospace', fontSize: 12, marginTop: 8 },
});
```

The example app in this repo has a richer version of this with tabs, a 3D animating scene, a per-surface probe table, and a share button. See [`example/App.tsx`](../example/App.tsx) if you want to clone that layout.

## 7. What you should see

On a PICO device with developer mode enabled:

- `isPicoBuild`: true. The pico flavor is active.
- `isPicoDevice`: true. Device detection matched `Build.MANUFACTURER`.
- `xrMode`: 'pico-os5' (or `'pico-swan'` if you set that).
- `appType`: '2d' for the panel starter.
- `platformSdkPresent`: reflects SDK class presence. A core-only app need not include PPS service clients. When you add service packages, the plugin selects their Maven dependencies and Gradle downloads them during the Android build. Class presence does not prove service initialization, credentials or full API implementation.
- Diagnostics: findings reflect your build, device and identity. Missing identity is informational about compilation; a 2D panel is intentionally absent from the immersive launcher.

On a mobile device or emulator (without `--variant picoDebug`):

- `isPicoBuild`: false, `isPicoDevice`: false.
- `xrMode`: 'mobile' (if `buildVariant: 'mobile'`) or the plugin-configured value (if the flavor manifest is still active but hardware isn't PICO).
- `build-device-mismatch` warning when the pico flavor runs on non-PICO hardware. Expected during dev.

## 8. Add the features your app needs

### Immersive scenes

Install a renderer release containing its matching native artifacts, following
the [template's Viro setup](../packages/expo-pico-template/README.md#adding-a-3d-renderer).
Add an actual immersive scene before opting into `appType: 'vr'` or `'mr'`.
`@expo-pico/core` configures Android but does not provide a 3D renderer.

For an immersive PICO OS 5 build, supply `PICO_APP_ID` (or
`PICO_PLATFORM_APP_ID`) registered for the Android package in your config,
then prebuild and rebuild. On the tested PICO 4 Ultra, the OS entitlement
service terminated immersive apps without a registered ID. Compiling without
credentials does not guarantee that the headset will launch the app, and
`entitlementCheck: false` does not disable the OS check. See the
[hardware investigation](./PICO-ENTITLEMENT-BLOCKS-LAUNCH.md).

### Platform Services

For example, add account support and its shared peer:

```bash
npm install "github:mikevocalz/expo-pico#release/platform-service-common" "github:mikevocalz/expo-pico#release/account"
```

Account autolinks and has no separate config plugin. Supply its credentials
through the core plugin's `platformService` options, then prebuild/build again. Use the
[release branch map](./INSTALL-FROM-GITHUB.md#branches) for other packages.
PPS native dependencies are automatic Maven dependencies. Check the
[package support matrix](../README.md#packages) before choosing a feature;
some APIs, including RTC and cloud storage, do not have native implementations.

### PICO OS 6 windows

Install `@expo-pico/spatial` from `release/spatial` and its shared-service peer,
then add `['@expo-pico/spatial', { enableSpatialSdk: true }]` to `plugins`.
The Spatial SDK 6 Maven dependencies are added automatically. On a compatible
device, use `getLayoutBridgeStatus()` before opening a WindowContainer.

Spatial anchors, live space transitions, scene mesh and core XR tracking,
haptics and passthrough controls remain unimplemented. Their capability flags
are false, or calls reject with `NOT_IMPLEMENTED`. Adding an AAR or declaring
a capability cannot implement those APIs.

## Troubleshooting

| Problem                                                                 | Cause or next check                                                        | Action                                                                                                                                                                                                  |
| ----------------------------------------------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Package install returns an npm 404 for `@expo-pico/*`.                  | The packages are distributed through GitHub release branches.              | Use the release URLs and install required peers from [Installing from GitHub](./INSTALL-FROM-GITHUB.md).                                                                                                |
| `Task :app:assemblePicoDebug not found`.                                | Plugin missing, or `buildVariant: 'mobile'`.                               | Add the core plugin, select `buildVariant: 'pico'`, and prebuild again.                                                                                                                                 |
| The starter appears in the PICO launcher's 2D apps section.             | The starter uses `appType: '2d'`.                                          | This is expected for its React Native panel. Follow immersive setup when adding a 3D renderer.                                                                                                          |
| An OS 5 immersive app builds but the OS closes it at launch.            | Device entitlement may require a registered app identity.                  | Supply the app ID for your Android package and rebuild. See the [device investigation](./PICO-ENTITLEMENT-BLOCKS-LAUNCH.md).                                                                            |
| A PPS call returns `SERVICE_UNAVAILABLE`.                               | Native module/service unavailable, wrong flavor, or unsupported host.      | Check the installed sibling, `picoDebug` variant and device, then inspect `getPlatformSdkProbe()`. Maven dependency-resolution failures appear in the Gradle build log; do not download unrelated AARs. |
| An XR or spatial call returns `NOT_IMPLEMENTED`.                        | The package has no native implementation for this method.                  | Check its capability flag and support matrix. Installing an SDK or rerunning prebuild does not enable it.                                                                                               |
| SDK 6 WindowContainer does not open.                                    | SDK unlinked or device is not a spatial platform.                          | Enable the spatial plugin's `enableSpatialSdk` option, rebuild, and read `getLayoutBridgeStatus()` for the specific reason.                                                                             |
| Doctor says `identity.missing` although an environment variable is set. | The dynamic config must pass that variable to `platformService.picoAppId`. | Use the config above and check it in the environment that runs prebuild.                                                                                                                                |
| The first Android build takes longer.                                   | Gradle downloads the declared dependencies and compiles native modules.    | Inspect the build log for progress or network errors. Later builds reuse normal caches. Prebuild itself does not resolve Maven artifacts.                                                               |

Still stuck? Check [FAQ.md](./FAQ.md) or open a [GitHub issue](https://github.com/mikevocalz/expo-pico/issues).
